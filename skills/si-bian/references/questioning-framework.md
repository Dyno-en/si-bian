# 追问框架

si-bian 的核心是一个词一个词追问。本文件是追问的完整框架，SKILL.md 中只引用，不展开。

---

## 五个追问维度

每个核心词都要过这五个维度。顺序可以调整，但五个都要问到。

### 维度一：具体指什么？

**目的：** 把抽象词拉回具体场景。

**标准问法：**
- "这个词在你这里具体指什么？"
- "举一个你经历过的例子。什么时候、什么人、做了什么、结果是什么？"
- "如果用一个具体的动作来描述这个词，是什么动作？"

**用户回答模糊时的追问：**
- "你说的'大概'，具体是多大范围？"
- "你说的'某种情况'，能说一个具体的吗？"
- "这个例子里，哪个动作算 X？哪个不算？"

**通过标准：** 用户能说出具体的场景、人物、动作、结果，而不是另一个抽象词。

---

### 维度二：边界在哪？

**目的：** 确定这个词什么时候成立、什么时候不成立。

**标准问法：**
- "什么情况下这个词成立？"
- "什么情况下这个词不成立？"
- "成立和不成立的分界线是什么？"

**用户回答模糊时的追问：**
- "你说'看情况'，具体看什么情况？"
- "有没有介于成立和不成立之间的灰色地带？"
- "如果把成立的程度打分，0到10分，几分以上算成立？"

**通过标准：** 用户能说出至少一个成立条件和一个不成立条件，且两者不重叠。

---

### 维度三：反例是什么？

**目的：** 找反例是确认边界最有效的方法。

**标准问法：**
- "有没有看起来符合 X，但实际上不是 X 的情况？"
- "有没有看起来不符合 X，但实际上是 X 的情况？"
- "如果有人用 X 这个词形容一件事，你会说'不对，那不是 X'，那是什么事？"

**用户说"没有反例"时的追问：**
- "任何情况都成立？那这个词就没有边界了，跟'一切'有什么区别？"
- "极端情况呢？比如……（给一个极端场景），这算 X 吗？"

**通过标准：** 用户能说出至少一个反例，并解释为什么它是反例。

---

### 维度四：跟什么容易混？

**目的：** 通过对比近义词，确认这个词的独特性。

**标准问法：**
- "这个词跟哪个词最容易被搞混？"
- "区别在哪？"
- "如果用错了词，会导致什么不同的结果？"

**用户说"没有容易混的"时的追问：**
- "那这个词是独有的？词典里没有近义词？"
- "如果让你用另一个词替换 X，你会用什么？为什么不直接用那个词？"

**通过标准：** 用户能说出至少一个近义词，并明确说出区别。

---

### 维度五：最小单位是什么？

**目的：** 拆到不能再拆，确认这个词是不是原子概念。

**标准问法：**
- "这个词能不能再拆成更小的部分？"
- "拆到不能再拆是什么？"
- "如果一个外星人不懂这个词，你怎么用最基本的动作解释给他听？"

**用户说"不能再拆了"时的追问：**
- "那这个词是最基本的？就像'红''走'一样不能再拆？"
- "如果一个小孩问你 X 是什么，你怎么解释？"

**通过标准：** 用户要么确认这是原子概念，要么拆成了更小的可验证部分。

## 两把收尾的刀

五个维度过完，每个词再各过一遍这两刀。它们专门用来识别"听着深刻、其实空转"的词。

### 第六刀：大白话删除测试（伪概念检测）

**目的：** 检验这个词是真在表达意思，还是在掩盖一块没搞懂的空白。

**标准问法：**
- "先把这个词从句子里拿掉，用最白的大白话把同一件事说一遍，说得出来吗？"
- "如果不许用这个词，你会怎么跟一个完全不懂行的人讲清楚？"

**两种结果：**
- 拿掉之后照样讲得清 → 这个词只是包装，让用户以后直接用那句大白话，别再用术语。
- 拿掉之后讲不清了 → 这个词正在替他掩盖一块没搞懂的地方，盯住这块，回到维度一、维度二继续追问。

**通过标准：** 每个核心词都要有一句"删掉术语后"的大白话版本；讲不出大白话的那个词，不许放进最终结论。

### 第七刀：换人换场景（意义即使用）

**目的：** 一个词的意思体现在"谁在什么场景下怎么用它"。同一个词不同人用法不同，本身就是混淆和争吵的来源。

**标准问法：**
- "这个词，你嘴里是一个意思；换一个人（你的客户、对手、家里人）说，他指的是同一件事吗？"
- "换一个场景，这个词还是这个意思吗？哪里变了？"
- "你们争的是不是根本不是一回事，只是共用了一个词？"

**通过标准：** 用户能说出这个词在至少两种人或两个场景下用法的差异；如果完全没有差异，要能说清为什么它在各处含义稳定。

## 追问的节奏

### 每次只问一个问题

不要一次问三个问题。用户回答一个，再问下一个。一次问多个问题会让用户选最容易的回答，跳过最难的。

### 接受停顿

用户说"让我想想""等一下"时，不要急着给提示。停顿本身就是思辨的一部分。

### 跑题时拉回

用户开始讲跟核心词无关的事时，直接拉回："这个跟 X 有什么关系？我们先把 X 搞清楚。"

### 用户说"我不知道"时

不要直接给答案。给一个暂定定义让用户判断：
- "你说的 X 是不是指……？对还是不对？"
- "如果是 A，那 X 是……；如果是 B，那 X 是……。你觉得哪个更接近？"

### 用户急着要结论时

告诉用户："结论要等边界清楚了才能给。现在 X 的边界还不清楚，下结论会错。"

## 常见失败模式

| 失败模式 | 表现 | 修正 |
|---|---|---|
| 审问感 | 用户觉得被盘问，不舒服 | 追问前加一句"我问这个是因为……"，说明追问的目的 |
| 跳步 | 还没问完一个词就跳到下一个 | 每个词必须过五个维度，确认边界后再跳下一个 |
| 替用户想 | 用户还没想，skill 就给了定义 | 只问问题，不给答案。用户说"我不知道"时给暂定定义让用户判断，不是直接给结论 |
| 用模糊词回答 | "大概""可能""某种程度上" | 这些词本身就是追问的起点，继续追问具体范围 |
| 硬套理论 | 找不到完全匹配的理论，硬套一个相似的 | 找不到就标注"经验判断，暂无理论支持"，不硬套 |
| 用新词解释新词 | 用另一个抽象词解释这个抽象词（"什么叫内耗？就是精神上的自我消耗"） | 解释里冒出的每个抽象词，当场拉来重新过五维；逼出大白话和具体场景 |
| 漂亮话盖"不知道" | 说不清时，甩一句正确但空的抽象话收场（"这就是人性""本质是认知问题"） | 点破"这句话换成具体场景是什么"，说不出就如实标"这里还没说清"，不许这样收束 |
| 把实践问题当文字题 | 对一个 Problem（只能做出来的事）反复追问，想逼出一句"终极答案" | 先用第〇步识别并声明这是 Problem，把目标改成"消除伪问题、看清真问题和边界"，不承诺文字答案 |

## 输出格式参考

追问完成后，输出结构化结论：

```
## 核心词：X

- 定义：……
- 成立条件：……
- 不成立条件：……
- 反例：……
- 近义词及区别：……
- 是否可再拆：……

## 核心词：Y
（同上）

## 结论
（用户自己想通的结论）

## 前人理论支持
- 理论A（作者）：支持结论的第 X 部分，核心机制是……
- 暂无理论支持：……

## 待确认
- ……
```
